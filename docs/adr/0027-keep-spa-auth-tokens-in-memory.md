# Keep SPA authentication tokens in memory

The React application authenticates with Auth0's redirect-based Authorization Code Flow with PKCE through the Auth0 React SDK. Short-lived access tokens and rotating, expiring refresh tokens remain in browser memory and are never written to localStorage or sessionStorage. Refresh-token iframe fallback and popup authentication remain disabled, and the SDK token worker is served from the application origin rather than a `blob:` URL. If Auth0 cannot renew the session with the rotating refresh token after browser state is discarded, the User authenticates again. The API validates signature, issuer, audience, and expiration and loads Role Assignments and relationship permissions from PostgreSQL rather than accepting them from client state. The occasional redirect tradeoff reduces persistent exposure of shared demonstration credentials. Exact browser allowances and provider evidence live in the [public portfolio threat model](../threat-model.md).
