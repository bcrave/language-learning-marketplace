# Use lightweight correlated observability

The deployed demonstration emits privacy-filtered structured JSON logs with Pino to Railway and reports unexpected browser and server failures plus selected traces directly to the exact hosted Sentry ingestion origin. Browser telemetry disables default PII, Session Replay, Feedback, screenshots, and attachments; filtering removes authorization data, GraphQL variables, URL query strings, and reviewer-entered content. Source maps upload from CI and are not served publicly, while a same-origin Sentry tunnel is excluded because it would add an abusable forwarding endpoint and application load. The API exposes separate liveness and readiness checks; readiness verifies PostgreSQL access and schema compatibility. The worker records a PostgreSQL heartbeat surfaced with readiness, fixture-generation, maintenance-lease, notification, and recovery state in a sanitized, read-only GitHub Actions diagnostics summary available only to the Project Owner; the public application exposes no diagnostics or owner route. For a Canonical Data Rebuild, that summary shows the active safe lifecycle state and latest terminal outcome, while GitHub Actions remains the detailed operational history and links to private Railway and Sentry evidence. Private alerts go only through existing owner-controlled email routes. A correlation identifier follows each operation through GraphQL, database transactions, durable events, worker attempts, notification intents, Audit Entries, logs, and error reports. Authentication secrets, contact details, private feedback, and complete GraphQL variables are excluded. This provides application-level diagnostics within the portfolio budget without operating an OpenTelemetry collector. The [public portfolio threat model](../threat-model.md) owns the browser policy, operational-authority boundary, and residual-risk boundary.
