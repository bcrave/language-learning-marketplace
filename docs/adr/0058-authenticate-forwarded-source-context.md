# Authenticate forwarded source context with a shared proxy secret

Caddy discards every inbound forwarding header, then presents the address it verified in `X-Verified-Source` and proves it is Caddy with `X-Proxy-Authorization`, a deployment secret the API holds as `API_TRUSTED_PROXY_SECRET` and compares in constant time before keying [ADR-0025](0025-bound-public-api-resource-consumption.md)'s per-source limits on that address. Railway private addresses are dynamic, so peer allowlisting is unavailable and the shared secret is the only in-application evidence of which peer connected. Context that is absent, unauthenticated, chained, or not a single address fails closed with HTTP 403 rather than falling back to the socket peer, which behind the [single public origin](0028-use-a-single-public-origin.md) is Caddy itself and would collapse the entire internet into one budget. Production requires the secret; without one the API keys on the connection's own address, which is what local development and the browser suite need. The salted hash of the key is retained, not the address. Rotation deploys Caddy and the API together and a mismatch stops public traffic, which is accepted because the alternative silently downgrades a per-source control to a global cap.
