# Expose task-oriented GraphQL operations

The GraphQL API exposes domain actions such as booking, cancelling, rescheduling, joining a waitlist, recording attendance, requesting absence, and substituting a teacher rather than generic CRUD or status-setting mutations. Mutations that create records or advance lifecycles require client idempotency keys, while naturally idempotent preference setters do not. Expected business failures such as a full session, insufficient credit, schedule conflict, or closed booking window return typed mutation outcomes that clients can handle explicitly; top-level GraphQL errors are reserved for malformed requests, authentication or authorization failures, and unexpected faults. This keeps domain rules behind intention-revealing operations and prevents clients from constructing invalid state transitions.
