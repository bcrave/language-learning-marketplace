# Separate public client configuration from secrets

Runtime secrets live in least-privilege Railway service variables, PostgreSQL uses a private Railway reference variable, and GitHub's protected production environment holds only an environment-scoped deployment token. Protected jobs consume secrets without returning them to the Project Owner's browser, diagnostics summaries, logs, artifacts, issues, Audit Entries, or runbooks. Routine evidence is redacted; when diagnosis requires raw configuration or provider evidence, the Project Owner inspects it only in the originating private provider console, and any runtime secret found outside its approved store is treated as exposed and rotated rather than preserved as evidence. Local overrides use ignored `.env.local` files while a committed `.env.example` contains safe placeholders, and Zod rejects incomplete startup configuration. Values embedded by Vite—including Auth0 domain and client ID, API audience, and browser Sentry DSN—are classified as public. Client secrets, management tokens, database credentials, deployment tokens, server monitoring credentials, and signing material never enter the frontend build. Secret scanning and push protection are enabled, and exposure requires revocation rather than repository-history cleanup alone.
