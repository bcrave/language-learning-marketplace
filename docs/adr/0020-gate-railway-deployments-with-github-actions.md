# Gate Railway deployments with GitHub Actions

GitHub Actions is the required quality gate for pull requests and pushes to `main`. It performs a frozen policy-checked pnpm install, formatting, linting, type checking, GraphQL generation-drift checks, domain tests, React component and accessibility tests, PostgreSQL integration and concurrency tests against a real service container, and the small Playwright journey suite. After successful checks on `main`, a serialized GitHub Actions release job orchestrates Railway rather than enabling independent service autodeploys. Deployment, manual Canonical Data Rebuild, recovery-drill, and recovery jobs reference a protected `production` environment whose Project Owner approval releases its least-privilege secrets for that run only. A manual Canonical Data Rebuild fixes the target to `production` and requires a non-secret reason plus an explicit acknowledgement that maintenance begins and mutable reviewer activity is discarded; the environment approval is its recorded second confirmation. Self-review remains available because this single-owner portfolio does not claim dual control. Completion or cancellation ends the elevation, and no production credential is returned to the owner session.

Routine Canonical Data Rebuild and indeterminate-state recovery are separate workflows. An ordinary rebuild refuses to run while an indeterminate state remains unresolved, and an exhausted automatic attempt is retried only through a fresh dispatch with a new reason and correlation identifier rather than GitHub's job-rerun control. Recovery first runs a protected assessment that preserves maintenance and recommends a bounded repair; a separate protected dispatch authorizes that state-changing repair. Releases and Canonical Data Rebuilds share one global maintenance lease: the current holder finishes without preemption, the other waits, and redundant scheduled rebuilds coalesce rather than canceling safe work in progress. Cancellation before lease acquisition is safe; after quiescence, cleanup must verify the prior state or the attempt becomes indeterminate. The project does not create paid Railway preview environments for pull requests because their value does not justify the portfolio deployment's $15 monthly ceiling.
