# Use resettable role-specific demo accounts

The public demonstration provides shared Auth0 identities for the Student, Teacher, Organization Manager, and Platform Administrator roles, with credentials presented to reviewers. All accessible people and activity are synthetic. Demo identities cannot change their authentication credentials or access deployment configuration or secrets, and public operations are rate limited. The Project Owner is a separate human operational principal anchored to a personally controlled, multi-factor-protected GitHub identity; Project Owner is not an application Role Assignment, and no shared identity has an owner elevation path or owner-only application route. A GitHub Actions operations workflow runs the Canonical Data Rebuild nightly, while a Project Owner may invoke the same routine workflow earlier; a separate owner-only recovery workflow handles an indeterminate rebuild state. During a Canonical Data Rebuild or recovery, the web application remains reachable with a localized refresh message, while authenticated operations receive `503 Service Unavailable` with `Retry-After`; admitted operations finish before quiescence, and rejected operations are never queued or presented as successful. Reviewers receive no workflow stage, failure code, or operational link. The interface otherwise warns reviewers that they share the environment and may observe concurrent changes.
